# DIVERGENCES — что провайдер делает правильно, а порт ещё не умеет

Ориентир — замороженный снимок документации H2 в `../h2sharp/docs/` и эталонный jar
`h2-2.5.259-SNAPSHOT.jar` на JVM. Не текущее состояние порта: порт растёт, и то, чего в нём
пока нет, — его работа, а не свойство H2.

Правило реестра: **провайдер не подстраивается под текущие пробелы порта.** Он генерирует то,
что требует H2 2.5, и записывает расхождение здесь.

**Не работает — значит дефект порта.** Тест, падающий из-за неперенесённой в порт функции,
помечается трейтом `BlockedByPort` и остаётся в наборе: он делает видимым, что порт до сих пор
не догнал H2. Два прогона:

* `dotnet test --filter "Category!=BlockedByPort"` — зелёный: всё, что может пройти, проходит;
* `dotnet test --filter "Category=BlockedByPort"` — перечень дефектов порта.

## Состояние

| Что | Состояние |
|---|---|
| Провайдер собирается | да, против релизного `linq2db 6.5.0` |
| Публичный API | `H2SharpTools.GetDataProvider`, `CreateDataConnection`, `H2SharpProvider`, `H2SharpVersion` |
| Генерация SQL | кавычки имён, типы H2, `LIMIT`/`OFFSET`, конкатенация через `\|\|` |
| Флаги возможностей | по H2 2.5, а не по текущему порту |
| Схемный провайдер | **отказывает**: каталог недоступен (см. ниже) |
| Перевод членов | только общий: даты и математика H2-специфичны, перевод не написан |
| Запрос, вставка, фильтр с параметром, порядок | работают против движка |

## Что было сломано и как починено

| Симптом | Причина | Починка |
|---|---|---|
| `INSERT INTO "Rows" (Id, Name, Price) VALUES (Id, Name, Price)` — значения выходили именами столбцов, и движок отвечал `ExpressionColumn.GetValue: no resolver is set on this expression` | Провайдер не переопределял `Convert`. Базовый `Convert` в linq2db пишет имя **как есть**, потому что префикс параметра — дело каждого провайдера: PostgreSQL пишет `:` , Oracle — `:` , а H2 должен писать `@`. Имена столбцов при этом тоже выходили без кавычек, а H2 складывает некавыченное в верхний регистр | `H2SharpSqlBuilder.Convert` переопределён: параметры — `@имя`, все идентификаторы — в кавычках |

Найдено это было **инструментированной локальной копией ядра linq2db**: в `BasicSqlBuilder` печатается
выражение-значение вставки, в `DataProviderBase.InitCommand` — сам SQL и параметры. Обе точки
включаются переменной окружения `LINQ2DB_DEBUG_SQL=1`.

Сама сборка переведена с пакета `linq2db` с nuget.org на локальную копию исходников: пакет
инструментировать нельзя. Свойство `LinqToDbProject` переопределяет путь, и сборка против
релизного пакета остаётся возможной.

## Пробелы порта, из-за которых провайдер пока не проходит запросы

| Чего нет | Симптом | Это |
|---|---|---|
| `INFORMATION_SCHEMA` | `Table "INFORMATION_SCHEMA" not found` | дефект порта |
| каталог движка из ADO-слоя | `H2Connection.Session` — `internal`, а `Schema.GetAllTablesAndViews` требует `SessionLocal` | дефект порта |
| `JOIN` | `FROM T3 a [*]LEFT JOIN T3 b` — ожидалось `statement` | дефект порта |
| `AS` перед алиасом таблицы | `SELECT a.Id FROM T3 AS [*]a` — ожидалось `statement` | дефект порта |
| identity DDL | `CREATE TABLE T1 (Id INT [*]GENERATED BY DEFAULT AS IDENTITY ...)` — ожидалось `)` | дефект порта |
| `CREATE SEQUENCE` | `CREATE [*]SEQUENCE "foo" AS integer ...` — ожидалось `TABLE` | дефект порта |
| `IN (подзапрос)` | `Parser.parseQuerySelect: IN with a subquery is not ported` | дефект порта |
| `MERGE` | `[*]MERGE INTO T AS t USING U AS u ...` — ожидалось `statement` | дефект порта |
| оконные функции | `OVER`/`FILTER` не портированы | дефект порта |

## Что схемный провайдер делает и почему

`GetSchemaProvider()` у linq2db — обязательный член, и его нельзя не реализовать. Каталог H2
(`INFORMATION_SCHEMA`) порт не читает, а до собственного каталога движка из ADO-слоя не дотянуться
(`H2Connection.Session` внутренний).

Поэтому `H2SharpSchemaProvider` **отказывает** с объяснением, а не возвращает пустую схему:
пустая схема — это утверждение о базе («в базе нет таблиц»), и здесь это утверждение о порте.

Как только `H2Connection.Session` станет публичным, схемный провайдер читает каталог движка
напрямую — это тот же запрос, который нужен EF-провайдеру для скаффолдинга.

## Открытые дефекты провайдера

| Что | Симптом | Где |
|---|---|---|
| перевод членов даты и математики не написан | `r.Date.Year` не переводится: H2 берёт часть даты своей функцией на каждое поле (`YEAR`, `MONTH`, `DAY`) и добавляет `DATEADD`, а не арифметикой PostgreSQL | `H2SharpMemberTranslator` |

Остальное в провайдере работает: запрос, вставка, фильтр с параметром и порядок — все идут
через linq2db в движок и возвращают то, что положили.

## Что сверено с эталоном

| Факт | Как проверено |
|---|---|
| H2 2.5 принимает и `FROM T a`, и `FROM T AS a` | jar на JVM: обе формы работают |
| грамматика пишет алиас как `[ [ AS ] newTableAlias ... ]` | `../h2sharp/docs/grammar.html` |
| у H2 2.5 нет `SCOPE_IDENTITY()`, `IDENTITY()`, `LAST_INSERT_ID()` | jar на JVM: все три «функция не найдена» |
| сгенерированный ключ приходит через ADO-канал generated keys | документация: «FINAL TABLE» и «retrieval of generated keys» |
| `DOUBLE` и `DOUBLE PRECISION` — один и тот же тип | порт: `"DOUBLE PRECISION", "DOUBLE", "FLOAT8"`; jar: оба принимаются |
| `VARCHAR`, `CHAR`, `NUMERIC`, `VARBINARY`, `UUID`, `JSON`, `CLOB`, `BLOB`, `TIMESTAMP`, `TIME`, `BOOLEAN`, `SMALLINT`, `INTEGER`, `BIGINT`, `REAL` принимаются | jar на JVM: все приняты |

## Набор тестов linq2db

В исходниках linq2db есть набор на 3300 файлов, и он **устроен по провайдерам**: каждый
data-driven тест в атрибуте перечисляет провайдеров, для которых он идёт.

| | |
|---|---:|
| атрибутов `IncludeDataSources` с явным списком провайдеров | 3734 |
| атрибутов без списка (то есть «для любого провайдера») | **0** |
| различных констант `TestProvName.*` | 115 |

Провайдер-независимых тестов нет ни одного, поэтому «просто навести набор на H2Sharp» нельзя:
список провайдеров перечислен в каждом атрибуте.

Что сделано, чтобы набор стал наводим:

* провайдер **регистрируется сам** — `H2SharpProviderRegistration` добавляет его в список
  известных linq2db при загрузке сборки (`DataConnection.AddProviderDetector`). Поэтому имя
  «H2Sharp» работает и в строке подключения, и в конфигурации набора;
* набор linq2db собирается и запускается против H2Sharp: проект тестов ссылается на провайдер,
  в `UserDataProviders.json` описана строка подключения, запуск — `linq2db.Tests.exe
  --provider H2Sharp`;
* прогон без списка провайдеров в атрибутах даёт 834 зелёных теста — это тесты самого linq2db
  (генерация SQL, маппинг, выражения), базы они не касаются.

Чтобы пошли провайдерные тесты, нужно расширить константы `TestProvName` (один файл, 115
констант) именем «H2Sharp». Тогда исполнятся около 3700 тестов, и большинство из них упадёт:
они проверяют SQL PostgreSQL, а не H2, и требуют возможностей, которых у порта пока нет
(`JOIN`, подзапросы, CTE, `MERGE`, identity, каталог). Это был бы тот же список дефектов
порта, что и в EF-наборе, но полученный от независимого источника.
